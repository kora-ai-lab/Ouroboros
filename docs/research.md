━━━ 1. COMPETITIVE LANDSCAPE (LIVE RESEARCH) ━━━

The personal AI assistant space is exploding. It divides into three clusters:

CLUSTER A — PERSONAL AI AGENTS (CAN ACT ON THE OS):
  OpenClaw — dominant open-source agent, massive community, CLI/messaging interface
  Claude Code — terminal-based coding agent (Anthropic)
  Copilot/Copilot Chat — IDE-embedded (Microsoft/GitHub)

CLUSTER B — LOCAL AI CHAT / MODEL RUNNERS (CHAT ONLY):
  Jan AI — open-source ChatGPT alternative, 4M+ downloads
  LM Studio — local model runner with SDK/API support
  GPT4All — local AI chatbot by Nomic
  Ollama + Open WebUI — CLI model runner + web chat UI

CLUSTER C — OS-INTEGRATED PRODUCTIVITY AI (ASSISTANTS, NOT AGENTS):
  Raycast AI — Mac launcher with AI chat, BYOK, AI Extensions
  Pieces — OS-level memory, snippets, LTM-2 engine
  ChatGPT Desktop — standalone chat app (OpenAI)
  Apple Intelligence / Siri — OS-level AI (Apple, macOS/iOS only)
  Microsoft Copilot — Windows 11 integration

Ouroboros's position: Bridges Cluster A (agentic, can act) + Cluster B (local-first, private) with Cluster C's UX polish (GUI, OS-integrated, consumer-friendly). This combination does not exist.

Primary loop type: **Product-Led Viral (demonstration-based)**
Why this loop: Ouroboros's floating bubble is inherently visible. When someone sees it on a colleague's screen, it generates curiosity. The bubble IS the growth artifact.   - The assistant fails publicly (someone asks "show me what it does" and it errors)

━━━ 7. CLASSIC BLIND SPOTS FOR THIS PRODUCT TYPE ━━━

Based on product type: Desktop App (Tauri) with OS-level integration.

1. **Cross-platform visual inconsistency** — Tauri renders on the OS's native WebView. A floating bubble that looks premium on macOS (WebKit) may look different on Windows (Edge WebView2) and Linux (WebKitGTK). Every platform needs visual QA. CSS that works on one renderer may break on another. Budget time for this — it's not "write once, run anywhere."

2. **OS permission model differences** — macOS requires accessibility permissions for overlay windows and global hotkeys. Windows has different security prompts. Linux varies by DE (GNOME, KDE, etc.). The "zero-config" promise is hardest to keep across OS permission gatekeeping. Each OS will gate the user with system-level permission dialogs that Ouroboros can't control.

3. **Antivirus false positives** — A Tauri app with OS-level access (global hotkeys, overlay windows, file system access, process execution) is a behavioral match for malware. Ouroboros WILL be flagged by Windows Defender, Norton, McAfee, etc. Code signing certs for Windows (EV) and macOS (Apple notarization) are not optional — they're mandatory pre-launch items. Budget $300-600/year for Windows EV cert, $99/year for Apple Developer Program.

4. **Local LLM performance is a first-impression risk** — If the first model the user tries runs at 3 tokens/second on their 8GB laptop, they'll uninstall and never return. The model download + loading experience must be managed: pre-download a small, fast model on install, show performance estimates based on detected hardware, and make cloud fallback one click away. Never let a new user's first experience be "waiting 5 minutes for a model to download then watching it generate 2 words per second."

5. **The self-evolving architecture is a v2 feature, not a v1 differentiator** — The user's vision of "creates, refines, and installs new tools for itself" is compelling long-term, but the v1 user won't care about recursive self-evolution. They want: bubble → type → get answer → execute task. Ship the engine in v1; the recursive tool-builder is v2's headline feature. Don't let the ambitious architecture delay the pragmatic MVP.
